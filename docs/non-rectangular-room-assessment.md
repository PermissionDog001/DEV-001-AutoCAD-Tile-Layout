# 非矩形房间能力边界与依赖评估

> 状态：历史评估；后续最小能力已按 `docs/orthogonal-simple-room.md` 进入实现与自动验证
> 日期：2026-07-21
> 前置条件：起铺控制接口冻结、自动验证通过，并形成可用 Git 基线后再立项

## 1. 结论

“选择 4 条及以上 `LINE` 的非矩形房间”不是把当前选择数量从 4 改为更多即可。它会同时改变边界拓扑、起铺锚点、网格裁切、输出碎线和测试模型，与本次起铺控制重叠修改核心几何、排版、选择和测试，因此当前不并行开发。

建议下一独立里程碑先支持“单个、无洞、无自交、WCS 轴对齐的简单正交闭合区域”，再根据真实图纸决定是否进入任意斜边多边形。洞口、柱和多外环继续拆开。

## 2. 两类几何必须区分

### 2.1 轴对齐凹/凸正交多边形

- 所有边平行于 WCS X 或 Y，仍可沿现有砖宽/砖高生成正交网格。
- 严格意义上，不含共线冗余点的凸正交多边形就是矩形。所谓“4 条以上的凸正交房间”通常只是矩形某一边被多条共线 `LINE` 分段，首先属于输入归一化，而不是新房型。
- 真正非矩形的简单正交区域通常包含凹角，例如 L 形、T 形或台阶形。
- 一条候选网格线与凹多边形相交后可能得到多个互不连续的室内区间，输出不再是一条贯穿房间的线。

### 2.2 任意斜边多边形

- 若仍使用 WCS 正交网格，斜边会产生大量不同长度的切割段，并放大端点、公差和极短碎线问题。
- 若希望“砖随房间旋转”，还必须定义局部坐标基准、主方向、砖宽/高朝向以及斜边房间没有唯一主方向时的选择规则。
- 通用线段—多边形求交、顶点命中、共线重叠和数值稳健性明显高于正交区域，不应与第一阶段正交凹多边形一起实现。

## 3. 闭合 `LINE` 输入的最低契约

下一里程碑至少需要冻结：

- 只接受同一模型空间、同一 WCS 高程的独立 `LINE`；
- 选择顺序和每条线方向任意，算法自行建立端点图；
- 每个合并后的顶点度数必须为 2，形成且只形成一个闭合环；
- 公差内端点允许吸附为同一顶点，但吸附规则必须确定，不能随选择顺序变化；
- 拒绝零长线、重复线、反向重复、部分重叠、T 形分叉、断口、多个分离环和悬挂边；
- 拒绝自交及非相邻边相触；是否允许相邻共线边应明确，通常应先合并；
- 洞口/柱需要内环语义，首个里程碑不支持，不能把多个闭合环误判成一个房间。

## 4. 网格裁切与碎线风险

矩形算法目前直接生成贯穿宽或高的一条线。非矩形需要对每条无限候选网格线与区域求交，再保留位于室内的一个或多个区间：

- 顶点正好落在网格线上时，必须使用一致的半开区间或奇偶规则，避免重复交点；
- 凹角可能把一条网格线切成多段，线数上限应按最终片段数而不是候选网格数计算；
- 相邻共线室内区间在公差内应合并，极短碎线应按集中阈值拒绝或丢弃，规则必须有测试；
- 不能跨越凹口、洞口或房间外部把两段误合并；
- 先分配全部交点再检查上限可能造成资源风险，需要延续 M6 的“先安全计数/流式验证，再创建结果”原则。

## 5. 与起铺控制的依赖

四角起铺对矩形有唯一含义，但凹多边形的包围盒角可能位于房间外，也可能没有对应边界顶点。因此非矩形里程碑不能直接假定本次四角枚举就是最终通用锚点。

在开发非矩形前应使用真实施工样例决定：

1. 继续以区域包围盒某角作为网格锚点，即使该角不在区域内；或
2. 升级为用户选择一个边界顶点/任意 WCS 基准点；或
3. 以指定控制墙线与端点定义局部起排。

这项决策直接影响余量分布和裁切结果，是非矩形能力的前置需求，不应在编码时临时决定。

## 6. 建议的下一独立里程碑

建议名称：`正交简单房间边界与裁切`。建议边界：

- 输入为 4 条及以上 WCS 轴对齐、同高程 `LINE`；
- 单一简单闭合环，无洞、无自交、无重叠、无 T 形分叉；
- 先支持共线分段矩形和 L 形两个代表类型；
- 输出仍为 WCS 正交网格，只保留区域内部线段；
- 明确起铺锚点后再冻结余量和切砖语义；
- 自动测试集中在端点图、闭环验证、凹角/顶点裁切、碎线合并、公差和最终片段上限；
- AutoCAD 实机只验证一个共线分段矩形、一个 L 形、一个断口/自交拒绝和一次撤销。

任意斜边、旋转网格、洞口/柱、多房间通缝分别作为后续能力，不放入该最小里程碑。
