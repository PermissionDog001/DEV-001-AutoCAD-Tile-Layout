# DR5 门块/门图元辅助识别规则与样本门

## 1. 状态与本轮决定

- 基线：`main@a2f2679`。
- 阶段：DR5 动态块首轮代码和 Debug/Release 自动质量门已完成；AutoCAD 2021 宿主验收因真实动态块样本为 0 而暂停。
- 结论：首次 AutoCAD 2021 验收确认 S1b-P2 句柄 `33C` 和 S1c-P1 句柄 `2D7` 都是顶层静态块，均正确返回 `Unsupported (StaticBlock)` 并回退。用户随后撤回 S2/S3 的动态块分类并确认现有图纸应当都没有动态块；未逐项取得 API 证据的 S2/S3 也不再作为候选或正样本。当前已确认动态块正样本和来源覆盖均为 0，预登记样本门槛不成立；静态块仍按本轮冻结规则拒绝。
- 已冻结：识别输入边界、唯一高可信门、歧义拒绝、失败回退到现有两点输入，以及样本充分性出口。
- 保持不变：`TILEDOORRECT` 的两点输入、`DoorOpeningPointAdapter`、DR2 排版核心、预览/翻转/接受流程、输出图层、单事务写回和一次撤销。
- 发布边界：不启动 M10，不修改程序集版本、`dist`、发布物、标签或远端。
- 路线决定：动态块路线暂停，等待真实动态块样本；下一独立任务转入“顶层静态门块辅助识别”的重新盘点与规则冻结。现有动态读取和识别代码暂予保留，静态块门禁在新范围完成样本证据、拒绝矩阵和自动测试前不得移除。

DR5 是可选辅助能力，不是新的排版算法。识别层最多只读地产生两个 WCS 候选端点；端点仍必须通过现有 `DoorOpeningPointAdapter`，再转换成与两点输入完全相同的 `DoorOpening`。

## 3. DR5 首轮能力边界

### 3.1 交互入口

- 房间边界和砖宽/砖高仍先按现有 `TILEDOORRECT` 流程取得并验证。
- 现有“门洞第一个边缘点”入口保持为默认可靠路径。DR5 编码时只允许在该入口增加显式 `对象(O)` 关键字；用户直接点取第一点时，继续执行现有两个点提示，不增加必答步骤。
- 不扫描整张图，不根据块名或图层自动挑门，也不把对象模式设为默认。
- 用户在对象选择时按 Esc 表示取消整个命令；取消不得被悄悄改成两点输入。
- 对象识别成功后仍显示现有门洞摘要、候选摘要和临时预览；不会直接生成分格线。

### 3.2 可选择的输入容器

首轮输入契约仍收窄为：用户显式选择一个模型空间顶层动态 `BlockReference` 的当前可见状态。现有图纸没有已确认动态块，原 S2/S3 候选分类也已由用户撤回。静态块和散 `LINE/ARC` 首轮统一返回 `Unsupported` 并回退两点，不进入实现范围。

共同约束：

- 输入来自当前数据库和模型空间，所有对象只读打开；
- 只分析当前选择，不追踪外部参照，不修改、分解、重定义或写回块；
- 动态块分析只能在内存中的只读当前可见几何副本上递归展开，并把几何变换到 WCS；不得修改可见性、距离、翻转或其他动态属性；
- 代理对象、外部参照、不可读或循环嵌套、非有限坐标、不同高程及非均匀缩放首轮均不支持；
- 镜像和旋转只有在 WCS 几何仍满足下述确定性签名时才可接受；
- 块有效名、普通块名、图层名、颜色、属性文字和动态参数名只可用于诊断，不得单独产生候选，也不得用来打破几何歧义。

后续只有在静态块或散图元分别取得至少两个独立来源的正负样本后，才重新评估扩展；不得把动态块通过结果外推为它们也受支持。

## 4. 冻结的几何识别签名

DR5 首轮只允许识别可解释的单扇平开门“铰点—门扇线—开启弧”签名：

1. 存在门扇 `LINE`，其一端 `H` 与 `ARC` 圆心在集中几何公差内重合；
2. 门扇线另一端 `F` 与该弧的一个端点在公差内重合；
3. 门扇长度与弧半径在公差内相等；
4. 弧的另一个端点 `J` 是关闭位置的另一门框边；
5. 识别层只提出门洞端点 `H/J`，随后必须由现有 `DoorOpeningPointAdapter.ProjectToRoomWall` 验证；
6. `H/J` 必须有限、同高程、投影后不同、落在同一面已验证矩形墙上且不超出墙段；
7. 当前选择中只能得到一个规范化后的 `H/J + 墙面` 结果。

弧方向、门扇左右手、块旋转、镜像和线端点顺序不得改变规范化结果。多条辅助线可以被忽略，但只要它们与其他弧/门扇组合出第二个不同候选，结果即为歧义。

首轮明确不识别：双扇门、子母门、推拉门、折叠门、无开启弧的简化门、三维门、仅靠块名/图层命中的门，以及需要猜测门宽或墙断口的符号。它们可在以后有独立样本和规则时扩展；当前一律回退两点。

## 5. 可信度模型

可信度是确定性的门控结果，不是未经校准的百分比或加权分数。

| 结果 | 条件 | 产品行为 |
|---|---|---|
| `High` | 输入类型受支持；恰好一个几何签名；恰好一个规范化端点对和墙面；现有点适配全部通过 | 显示“对象辅助识别”摘要，进入现有排版计算和预览 |
| `Ambiguous` | 存在两个或更多不同端点对、不同墙面或无法唯一确定哪个弧/门扇属于目标门 | 明确报告歧义，回退两点 |
| `Unsupported` | 对象/门型/变换不在首轮范围，或没有完整几何签名 | 明确报告不支持，回退两点 |
| `Invalid` | 得到候选但现有点适配拒绝，例如跨墙、超墙段、重合、不同高程或非有限坐标 | 显示现有几何拒绝原因，回退两点 |

只有 `High` 可进入预览。不存在“中可信先猜一个”“按名称优先”“选择最近墙”“选择最长弧”或“选第一个候选”的路径。

## 6. 歧义拒绝规则

出现以下任一情况必须拒绝对象结果并回退，不得静默择一：

- 同一块或选择集中识别出多个不同门洞；
- 两个候选共享部分图元但给出不同铰点、门框边或门宽；
- 候选分别落在不同房间墙，或靠近墙角而现有适配得到公共墙歧义；
- 双扇/子母门产生两组开启弧且尚无冻结的合并规则；
- 块名、图层或属性暗示“门”，但几何签名缺失或冲突；
- 几何只在无限延长墙线上相交，实际端点不在墙段；
- 需要典型门宽、最近距离、对象创建顺序、句柄顺序或人工经验才能补足结果；
- 非均匀缩放把圆弧变成椭圆，或嵌套/代理几何无法无损转换到 WCS；
- 识别结果与用户已选择的矩形房间不一致。

拒绝是正常安全结果，不是程序异常。

## 7. 回退到现有两点输入

- 对象模式得到 `Ambiguous`、`Unsupported` 或 `Invalid` 时，先显示一条可解释原因，再自动回到现有“门洞第一个边缘点”提示；房间边界和砖规格保持不变。
- 回退后完整复用现有第一点、第二点、公差投影、错误重试、摘要、候选、翻转和接受流程，不建立第二套手动逻辑。
- 对象识别后的预览选择 `重选(R)` 时，也回到同一门洞输入入口；用户可直接点两点，或再次显式选择 `对象(O)`。
- 用户在对象选择阶段按 Esc、在回退后的第一点/第二点按 Esc，均按现有取消语义结束，零写入。
- 识别失败、回退、重选、预览和取消均不得访问、创建或修改 `TILE_LAYOUT_DOOR_RECT`；只有最终接受后才沿用现有单个写事务。
- 门块、散图元和四条房间边界始终只读；插件不自动保存 DWG。成功写回仍须可紧接一次 `U`/`UNDO` 整体撤销。

## 8. 样本接收与脱敏要求

每份样本必须是新的脱敏副本，不得用正式图或仅改文件名的同哈希副本充数。每个样本配同名说明，至少记录：

- 匿名来源族 ID；来源独立性的说明，复制、另存、旋转或镜像不算新来源；
- DWG 版本、文件大小、SHA-256、单位、模型空间、World UCS 和统一高程；
- 门型、容器类型、块是否动态、嵌套层级、旋转/镜像/缩放状态及所含实体类型；
- 房间四条边界、人工确认的门洞墙和两个精确 WCS 端点；
- 预期结果为 `High` 或回退；回退时写明唯一原因；
- 已移除项目名、人员、地址、图签、文字/属性、外部参照、底图和无关业务对象；
- 样本使用授权和是否允许进入 `tests/fixtures`。未经 Git 授权的 DWG 继续忽略，只在受控本地副本验收。

脱敏不得破坏本次要验证的块结构、动态状态、嵌套关系和门扇几何。若必须重建门符号，需标记为“合成样本”，不能冒充真实来源。

## 9. 进入编码前的样本充分性门

只有同时满足以下条件，才重新评估是否编码：

1. 至少 3 个相互独立的脱敏来源族；同一原图的副本、另存、旋转、镜像和版本转换只算 1 个来源。
2. 每个来源至少有 2 个经人工标注的正样本，且每个拟支持的输入容器至少在 2 个独立来源中出现。若做不到，就从首轮支持范围删除该容器。
3. 正样本覆盖四面墙（允许从真实样本派生旋转测试，但派生件不增加来源数）、左右手/镜像、线端点和弧方向反转、非原点 WCS，以及静态/动态状态中实际宣称支持的组合。
4. 每个来源至少包含 1 个近似但应回退的负样本；全矩阵还须覆盖双扇、多候选、无弧、块名命中但几何不符、跨墙/墙角、超墙段、不同高程、非均匀缩放、外部参照/代理和用户取消。
5. 所有正样本都有人工确认端点；所有负样本都有单一、可审查的回退原因。不能只记录“识别失败”。
6. 验收矩阵要求：支持样本的墙面和两个端点 100% 与人工标注一致；歧义/负样本自动接受数为 0；任何未覆盖单元不得被写成“支持”。

数量只是最低门槛，不能替代覆盖面。若新增来源暴露冲突，应先收窄规则或保留回退，不得为通过旧矩阵而增加猜测。

## 11. 当前出口

精度结论已形成：S1b-P1 的东墙非 WCS 轴对齐，因此在房间验证阶段前置拒绝；S1b-P2 和 S1c-P1 顶层块参照经 AutoCAD 2021 确认为静态块，均已正确触发 `StaticBlock` 回退。用户确认现有图纸应当都没有动态块，并撤回 S2/S3 的动态分类；当前动态正样本和来源覆盖均为 0，预登记完整样本门槛不成立。DR5 首轮代码和自动质量门保留，但完整宿主验收暂停；取得满足矩阵的真实顶层动态门样本前不得声明 DR5 实机通过。若要改为支持现有静态块，必须另行冻结新范围，不能直接放开当前门禁。继续严格保留 DR4 两点默认与失败回退，不启动 M10，不修改版本或发布物。

## 12. 首轮实现与自动验证记录

2026-07-28 从 `main@a2f2679` 和本轮四份预期 DR5 文档改动继续编码，未覆盖或丢弃既有样本盘点记录。

- 核心新增宿主无关的 `ArcSegment3D`、`DoorGeometryRecognizer`、确定性状态和拒绝码。识别只组合 `LINE` 与 `ARC`：门扇线一端匹配弧心、另一端匹配一个弧端点、线长匹配弧半径；输出仅为铰点和关闭位置门框端点。
- 同一端点对由不同图元重复表达时规范化为一个候选；两个或更多不同端点对一律为 `Ambiguous`。算法不读取块名、图层、属性、门宽、句柄或对象顺序，也没有最近、最长或第一个候选规则。
- `DoorObjectRecognitionCoordinator` 把唯一几何候选继续送入原有 `DoorOpeningPointAdapter.ProjectToRoomWall`。只有几何唯一且点适配成功才为 `High`；点适配失败统一为 `Invalid` 并保留原有几何拒绝原因。
- AutoCAD 读取器只接受当前数据库模型空间顶层动态 `BlockReference`，以只读事务取得当前可见状态的内存展开副本，递归收集 WCS `LINE/ARC`。它不调用块编辑、分解命令、动态属性写入、保存或数据库实体追加。
- 静态块、散图元、非模型空间/非顶层对象、XREF、代理、循环或不可读嵌套、非 WCS XY 平面弧、零缩放和非均匀缩放均有明确 `Unsupported` 拒绝码。旋转、镜像和均匀缩放只有在展开后的 WCS 线弧仍满足同一签名时才可能进入 `High`。
- `TILEDOORRECT` 只在原“门洞第一个边缘点”提示增加 `[对象(O)]`。直接点第一点仍进入原第二点提示；对象失败显示 `Ambiguous/Unsupported/Invalid + 拒绝码 + 原因` 后回到同一第一点入口；对象选择按 Esc 取消整个命令。
- 对象 `High` 后继续使用原门洞摘要、DR2 候选计算、临时矢量预览、翻转、重选、接受和 `TILE_LAYOUT_DOOR_RECT` 单事务写回。`DoorLayoutPreviewSession.IsWriteAuthorized` 只在接受终态为真，取消、重选和预览中均不能进入写回。
- 新增 24 项宿主无关测试，完整套件由 116 增至 140。覆盖线/弧端点反转、四向旋转、镜像、大 WCS 偏移、重复几何规范化、双扇/多候选、无弧、非门几何、非有限坐标、点适配失败、全部冻结拒绝码、静态/散图元/XREF/非顶层/非均匀缩放拒绝、两点默认、对象失败回退、对象 Esc、第二点 Esc 和接受前零写回授权。
- 完整解决方案 Debug/Release 均在 `build/dr5-solution` 隔离目录 0 警告、0 错误重建通过；两种配置自动测试各 `140/140`。正式插件另在 `build/dr5-plugin/Debug` 编译通过：`TileLayout.AutoCAD.dll` 为 46,592 字节、SHA-256 `33371FE7C11AB68B908C7BDDD04699768460B9244496C01815FC3D54B877E65C`。隔离输出未复制 Autodesk Managed DLL。
- 标准 `build/plugin/Debug` 因现有 AutoCAD 会话加载而被锁定，没有强制关闭宿主或覆盖 DLL；隔离构建避免干扰当前会话。
- `TileLayout.AutoCAD.dll` 和 `TileLayout.Core.dll` 的文件版本保持 `0.1.0.0`；没有修改 `dist`、发布物、Git 标签或远端，没有提交或推送，也没有操作 `inputs` 中的 DWG。

自动结果不替代真实动态块在 AutoCAD 2021 中的读取证据；DR5 在第 13 节完成前仍不能声明宿主验收完成。

## 13. AutoCAD 2021 脱敏工作副本一次性实机验收清单

本轮只由用户操作 AutoCAD；全部测试使用从 `inputs/dr5-intake` 新复制到 `work/dr5-acceptance` 的工作副本，不打开或保存 `inputs` 原件。开始前完整退出已加载旧同名 DLL 的 AutoCAD 会话并选择“不保存”，记录每份工作副本的大小和 SHA-256；新会话只 `NETLOAD` `build/dr5-plugin/Debug/TileLayout.AutoCAD.dll`，并核对该 DLL 为 46,592 字节、SHA-256 `33371FE7C11AB68B908C7BDDD04699768460B9244496C01815FC3D54B877E65C`。确认 `INSUNITS=4`、`TILEMODE=1`、World UCS。

1. **命令和默认两点回归**：在任一合格四线矩形工作副本执行 `TILEDOORRECT`。确认第一点提示新增且仅新增 `[对象(O)]`；不输入 `O`，直接点取人工标注的两个端点。预期仍出现原第二点提示、原门洞/候选摘要和预览；选择 `C` 后 `TILE_LAYOUT_DOOR_RECT` 不存在或对象数与命令前一致。
2. **动态块正样本**：当前没有真实动态块样本，本项暂停且不得对 S2/S3 预期 `High`。后续只有在取得满足预登记矩阵的新脱敏动态块样本后，才恢复墙面、端点、洞宽、预览和零写入验收。

   | 样本 | 预期墙面 | 人工端点 |
   |---|---|---|
   | S2-P1 | 北墙 | `(3479.4031,3615.9558,0)`～`(4479.4031,3615.9558,0)` |
   | S2-P2 | 东墙 | `(6379.4031,2597.6302,0)`～`(6379.4031,1597.6302,0)` |
   | S3b-P1 | 北墙 | `(5715.6686,3152.5183,0)`～`(4715.6686,3152.5183,0)` |
   | S3b-P2 | 东墙 | `(7890.6686,1448.7921,0)`～`(7890.6686,2448.7921,0)` |

3. **规范化和只读检查**：本项随动态正样本暂停。恢复后分别记录块的句柄、位置、旋转、比例、动态属性值和可见状态；对象 `High` 后在预览选 `C`。预期镜像/旋转样本仍只产生一个规范端点对，门块和四条边界的上述属性完全不变，正式输出图层/对象数不变。
4. **双扇和多候选拒绝**：在 S1 或 S3 工作副本对双扇门执行对象模式。预期为 `Ambiguous (MultipleDistinctSignatures)`，不按最长弧、最近墙或对象顺序择一，并自动回到第一点入口。若样本当前可见状态未形成两套完整签名，应为 `Unsupported (NoCompleteSingleSwingSignature)`，仍不得 `High`。
5. **非门和无签名拒绝**：分别选择 S2b 的非门物体及 S3 的 N2/N3。预期为 `Unsupported`，原因明确为对象类型不支持或无完整单扇线弧签名，然后回到第一点入口；三项自动接受数必须为 0。
6. **静态块与散图元拒绝**：S1b-P2 句柄 `33C` 和 S1c-P1 句柄 `2D7` 已实机确认返回 `Unsupported (StaticBlock)` 并回退两点；二者块名均为 `$DorLib2D$00000001`，比例均为 `1000/-1000/1000`，负 Y 只是均匀镜像。另在对象模式选择单条散 `LINE` 和单条散 `ARC`，预期为 `UnsupportedObjectType`，不要求用户修改原对象，也不进入预览。
7. **非均匀缩放拒绝**：仅在一次性工作副本中复制一个正样本动态块，把副本设置为 X/Y 不同的非均匀比例；不要改原样本块。选择副本时预期 `Unsupported (NonUniformScaling)`，原块和输出对象数不变。测试后不保存工作副本。
8. **点适配失败**：使用只在工作副本中移动的正样本副本，使识别出的两个端点离开已选矩形墙或跨出墙段；不要移动原样本。几何签名仍唯一时预期 `Invalid (PointAdapterRejected)` 并显示原有“靠近房间墙/超出墙段/同墙”等具体原因，然后回到两点输入；不得创建图层。
9. **失败后两点回退**：紧接步骤 4、5、6、7 或 8 的一次失败，不退出命令，直接点取该房间的人工门洞两点。预期完整进入原摘要、候选和预览；选择 `C` 后仍零写入。这证明失败没有建立第二套手动流程。
10. **Esc 和重选**：第一点提示输入 `O`，在对象选择提示按 Esc，预期取消整个 `TILEDOORRECT`，不得强迫回到两点。另以一个 `High` 样本进入预览后选 `R`，预期返回同一个“第一点或对象(O)”入口；随后可直接点两点。再分别在第一点和第二点提示按 Esc，均应取消且零写入。
11. **每来源接受、计数和一次撤销**：S1、S2、S3 各选一个 `High` 样本进入预览，记录候选摘要报告的分格线数 `N`，选择 `A`。预期只在 `TILE_LAYOUT_DOOR_RECT` 新增恰好 `N` 条分格线，门块和边界不变；成功后不插入任何其他命令，立即一次 `U`，预期本轮 `N` 条全部消失，图层恢复命令前状态。
12. **兼容与上限回归**：至少各执行一次 `TILE600`、`TILELAYOUT`、`TILEORTHO` 原合法小样例；再执行 DR4 的 10002 × 0.5 mm、砖宽/高 1/1 mm、南墙两点 `(100,0)/(200,0)` 上限样例。预期三个旧命令行为不变；`TILEDOORRECT` 仍在 10001 条时于正式图层创建/修改前拒绝。
13. **关闭不保存与哈希**：关闭全部 DR5 工作副本并选择“不保存”。核对每份工作副本的大小和 SHA-256 与步骤前一致；`inputs/dr5-intake` 原件保持只读、大小和既有哈希不变。

每一步记录：样本 ID、步骤号、命令行全文、识别状态/拒绝码、墙面、洞宽、输出图层前后对象数、门块/边界是否变化和撤销结果。任一步出现异常时停止该文件后续判定，关闭且不保存，并集中反馈上述记录；不要在异常状态下保存或改写样本。
